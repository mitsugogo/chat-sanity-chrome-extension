# ChatSanity

YouTube Live Chat向けのManifest V3 Chrome拡張です。日本語チャットをルールベースで分類し、必要な場合だけChrome内蔵AI（Gemini Nano / Prompt API）またはLM Studioへ、曖昧なコメントとルール未一致から抽選された少数のコメントを送ります。処理は端末内で完結し、クラウドAIは使用しません。AIがsafeと確定した本文は、本文を保存せずSHA-256フィンガープリントだけを端末内へ記憶します。ユーザーが明示的に記録したフィードバックは、後述のとおり拡張機能内のIndexedDBへ保存します。

## Download

最新バージョンは
[GitHub Releases](https://github.com/mitsugogo/chat-sanity-chrome-extension/releases/latest)
からダウンロードできます。

### Install

1. Releases から最新の `ChatSanity-*-chrome.zip` をダウンロード
2. ZIPを任意のフォルダへ展開
3. Chromeで `chrome://extensions/` を開く
4. 「デベロッパー モード」を有効化
5. 「パッケージ化されていない拡張機能を読み込む」を選択
6. 展開したフォルダを指定

## 開発

```powershell
pnpm install
pnpm dev
```

Chromeの `chrome://extensions` で「デベロッパー モード」を有効にし、WXTが生成した `.output/chrome-mv3-dev` を「パッケージ化されていない拡張機能を読み込む」から選択します。

本番用ビルドは次のコマンドで `.output/chrome-mv3` に生成されます。

```powershell
pnpm build
```

## ローカルAI

詳細設定の「AIプロバイダー」では、Chrome内蔵AIとLM Studioの優先順位を選べます。既定の「自動」はChrome内蔵AIを優先し、利用できない場合だけLM Studioへフォールバックし、どちらも利用できない場合はルール結果を使用します。「Chrome 内蔵AI」「LM Studio」「使用しない」も選択できます。

Chrome内蔵AIはChrome 138以降の拡張機能向けPrompt APIをfeature detectionして使用します。`downloadable`または`downloading`はライブチャット中の利用可能状態とはみなさず、勝手にモデル取得を開始しません。詳細設定の「Chrome AIを準備する」を押したユーザー操作からだけモデルを取得します。分類ではsystem promptだけのbase sessionを遅延作成し、batchごとに`clone()`したsessionを使って破棄します。Service Worker再起動時はsessionを再生成します。

## LM Studio

1. LM Studioでモデルを読み込み、Developer画面からローカルサーバーを開始します。
2. ChatSanityの詳細設定で「AIプロバイダー」の「LM Studio」を選択します。
3. ローカル接続の権限を許可し、モデルを選択して設定を保存します。

初期接続先は `http://127.0.0.1:1234` です。コメント本文はlocalhost以外へ送信せず、通常のチャット履歴も永続保存しません。AIのsafe判定は正規化本文のSHA-256フィンガープリントと判定メタデータだけを`storage.local`へ最大1,000件保存し、同じ本文を別の配信でも完全一致で許可します。本文、投稿者、チャンネル、配信情報はこの記憶へ保存しません。ユーザーが明示的に登録するフィードバックは、この通信とは別に拡張機能内へ保存されます。LM Studioが利用できない場合はルールベース判定へ戻ります。

### 調整できる項目

- **AI応答の待ち時間**: LM Studioは既定10秒、1〜60秒で調整できます。Chrome内蔵AIの推論timeoutは10秒です。チャットはどちらも500msでルール結果を表示し、開始済みの推論を中断せず、後からAIが成功した場合に更新します。
- **応答形式**: JSON Schemaが既定です。モデルが対応しない場合はJSON Object、またはテキスト形式を選べます。どの形式でも返されたJSONのID・カテゴリ・スコアを検証し、不正な結果は適用しません。
- **最大件数**: 200msごとにまとめ、Chrome内蔵AIを優先する自動モードとChrome内蔵AI単独では最大8件、LM Studio単独では設定した最大1〜20件を送ります。同時実行は1バッチ、待機も1バッチまでです。待機列が満杯になると最古のコメントをルール結果へ戻して最新コメントを受け入れ、1.25秒を超えた待機コメントはAIへ送りません。
- **AI対象スコア**: 0.35〜0.80の範囲内で下限・上限を調整できます。無効にしたカテゴリや重みはAI判定にも反映します。
- **未判定コメントの再確認**: ルール未一致かつ0点のコメントは、通常は一部だけZero-score Auditとして送信します。LM Studio単独では既定3%・最大12件/分・同時20件、Chrome内蔵AIを優先する構成では基礎確率1%・最大3件/分・同時2件を上限とします。初見の本文・婉曲的な催促などで確率を補正します。設定画面の「ルール未一致をすべてAIで確認」を有効にすると抽選と監査上限を使わず全件をAIキューへ渡しますが、キュー混雑時のload sheddingは維持します。明示的な安全判定や除外対象は送信しません。
- **文脈補正**: 同一投稿者の直近60秒のリスク投稿、直近のリスク投稿、チャット全体の対立度だけを補助情報としてローカルAIへ渡します。投稿者名、メンバー状態、DOMは渡しません。対立度は判定スコアを少し補正するだけで、全コメントを一括で隠しません。
- **閲覧中の一時ルール**: 強い問題と判定された同文を再利用し、異なる3本文で一致し、文節単独でも同じカテゴリの高スコアをAIが返した場合に一時ルールへ昇格します。現在のチャットフレーム内だけで使い、再読み込み・設定変更でリセットします。問題判定の本文や一時ルールは永続保存しません。
- **キャッシュとsafe記憶**: 通常のAI結果は`providerId + promptVersion + 正規化本文`ごとに最大10分だけ再利用し、Provider・prompt・設定変更またはタブ終了時に破棄します。`safe`結果だけは本文のSHA-256フィンガープリントを最大1,000件保持し、配信やAIの有効状態をまたいで完全一致で再利用します。ユーザー指定のブロック語句、非表示ユーザー、Human Feedbackによる訂正はsafe記憶より優先します。
- **繰り返し投稿者**: 同じ配信でぼかし・非表示が続いたユーザーは、そのセッション内でスコアを上げて非表示側へ倒します。閾値に達したチャンネルは詳細設定の「非表示ユーザー」へ記録し、他の配信でも非表示にします。表示したい場合はホワイトリストへ移せます。自分の投稿は常に表示（0.00）です。

カテゴリは指示・指示厨、責任追及、人格・能力攻撃、比較・対立煽り、自治・コメント欄の喧嘩、不満・愚痴、鳩・別視点、ネタバレに分かれ、カテゴリごとに「スコアに従う」「表示」「薄く表示」「ぼかす」「非表示」を選べます。配信者・モデレーター・自分の投稿・スーパーチャットは判定対象外で、デバッグモードでもNGボタンを表示しません。モデレーターの投稿は設定に応じてチャット上部へ固定し、複数ある場合は最後の投稿を前面に表示します。固定行の背景色はYouTubeのライト／ダークテーマに追従します。`非表示`は元ノードを削除せず、`ぼかし`をアイコンと発言者IDまで広げた表示です。本文をクリックすると一時的に原文を確認できます。

「デバッグモード」をONにすると、チャットの対応済み行へ薄いスコアと小さな「NG」ボタンを付け、AI判定中には「AI検閲中」を表示します。「NG」を押すと、表示中の安全なコメントは見逃しとして、対応済みコメントは訂正としてカテゴリを選んで記録できます。詳細設定の診断プレビューでは「正しい / 間違い」も記録できます。デバッグ履歴では、本文・カテゴリ・スコア・判定元・対応理由を最大200件確認でき、Zero-score Audit由来の判定には監査確率と抽選値も残します。デバッグ履歴自体はメモリ内だけに保持し、デバッグOFF、設定変更、タブ終了で消去します。

## フィードバック

詳細設定の「診断プレビュー」では、判定結果に「正しい / 間違い」を付け、間違いの場合は本来のカテゴリを選べます。デバッグ中の実チャットでは、許可されたコメントも問題として報告できるため、誤検知だけでなく見逃しも蓄積できます。

記録した本文、正規化本文、予測カテゴリ・スコア・アクション、訂正カテゴリ、ルールID、feature、判定元と時刻は、Chrome同期設定とは別の拡張機能内IndexedDBに保存されます。同じ正規化本文に対する一意の最多カテゴリが60%以上の支持を得た場合だけ、次回の判定で保守的に反映します。訂正から一般的な単語ルールを自動追加したり、`rules.ts`を自動変更したりはしません。

フィードバックは自動的に外部送信されません。詳細設定の「フィードバック」から一覧・ルール別統計を確認でき、ユーザー操作でJSONLとしてエクスポート、または全件を消去できます。v1では、保存済みフィードバックをLocal AIのfew-shot例として自動送信しません。

## デバッグ機能について

診断プレビューは現在の編集内容で本番と同じAI結果合成を試します。AIが失敗した場合はルール結果と失敗理由を表示します。単発の診断では実チャットの連投履歴や一時学習は再現しません。

一時学習の根拠は、ルールスコアがAI対象の曖昧域に入ったコメントへのAI判定です。文節単独の確認もこの条件に従います。Zero-score Auditの結果は、全件AIチェックを有効にした場合も正規化本文のキャッシュにだけ保存し、自動的な一時ルール生成には使いません。閲覧時間だけで精度向上を保証するものではありません。

日本語の命令形・煽り・皮肉・鳩・比較・杞憂・ネタバレは表記揺れを正規化して判定します。短い応援や一般的な質問との誤検出を抑えていますが、文脈のない短文を完全に分類できるものではありません。通常プリセットでは指示などのカテゴリが無効なので、箱ゲー・完全平和かカテゴリ設定で調整してください。実データから抽出した評価用フィクスチャは匿名化して `tests/fixtures/chat-classification.json` に含め、元のチャットログや投稿者IDはリポジトリへ含めません。

LLMなしでも、対象検出（人物・役割／ゲーム内対象）、命令形、責任追及、能力攻撃、比較、コメント欄への介入、不満、疑問形、笑い・応援の安全文脈を小さなfeatureとして組み合わせてスコア化します。人物を指さない「武器が使えない」や、応援の「ナイス指示」は強い攻撃判定になりません。曖昧な0.35〜0.80は、LLMがない場合は文脈補正を加えても原則allowを維持します。

ルールには`BACKSEAT_001`や`BLAME_FEATURE_001`のようなIDが付き、デバッグ履歴で理由・特徴・文脈補正と一緒に確認できます。`tests/evaluation/`には、匿名化したpositive、hard-negative、ambiguous、contextのフィクスチャと、precision／recall／false-positive-rateを確認するテストを置いています。元の`BMoPMmtKosQ`チャット全体は保存しません。
